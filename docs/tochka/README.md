# Точка Банк: как устроен API

Не один API, а **шесть продуктов на трёх разных хостах**, объединённых общей документацией.
Это первое, что ломает интеграцию: токен и базовый URL у них разные.

| Продукт | Что делает | Хост |
|---|---|---|
| `tochka-api` | счета, балансы, выписки, платежи, СБП, платёжные ссылки, вебхуки | `enter.tochka.com/uapi/` |
| `pay-gateway` | интернет-эквайринг: формы оплаты, возвраты, токены карт | `enter.tochka.com/uapi/**pay/**` |
| `cyclops` | номинальные счета: бенефициары, сделки, виртуальные счета | **`api.tochka.com`**`/api/v1/cyclops` |
| `medusa` | маркетплейс-выплаты: получатели, заказы, выплаты по СБП и на карты | `enter.tochka.com/uapi/` |
| `express-credit` | экспресс-кредиты | `enter.tochka.com/uapi/` |
| `info` | справка о клиенте | `enter.tochka.com/uapi/` |

Тестовые серверы есть **не у всех**: `tochka-api` и `info` — `enter.tochka.com/sandbox/v2/`,
`cyclops` — `pre.tochka.com`, `medusa` — `stage-uapi.tochka.com`, у `pay-gateway` — нет вовсе.

## Спецификации

Открытой спецификации у банка нет: портал `developers.tochka.com` отдаёт её по одной
операции, внутри JS‑бандлов. Копия в машинном виде лежит в [`api/`](api/) — **167 операций**,
скачивается `python scripts/download_tochka_specs.py`. Как именно она достаётся — в
[ловушках](traps.md#спецификации-нет-в-открытом-виде).

## Что нужно, чтобы начать

1. Расчётный счёт в Точке.
2. Приложение в личном кабинете → `client_id` и токен Open Banking.
3. Разрешения (`permissions`) под нужные методы — выдаются отдельно, см. [auth.md](auth.md).
4. Для `cyclops`, `medusa`, `pay-gateway` — **отдельное подключение продукта**: они живут на
   своих хостах и общим токеном Open Banking не открываются.
